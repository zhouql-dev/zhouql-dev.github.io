把 MEMORY.md 变成可训练的动作

How to Train Memory Writing for Continual Learning · RIME
Qixin Xu, Yuxiao Qu, Ian Wu, Aviral Kumar — CMU · 2026.11
cmu-aire.github.io/RIME

每条 agent 的 MEMORY.md 背后，都有一个从未被训练过的 writer——一段 prompt 临时驱动它决定"哪些经验值得留给下一个任务"。CMU Aviral Kumar 组的 RIME 问了个更底层的问题：写记忆这个动作本身，能不能被梯度训练？答案是能，但前提是先认识到一个不舒服的事实：只训练 writer 是没用的。

一、问题

Agent 的真实工作流很少是孤立任务：在同一个代码库连续修 19 个 bug，前面的经验本该让后面越修越快。理想是 deployment-time continual learning——不更新权重，把经验蒸馏成一段文本记忆在任务间传递。现有方案清一色靠 prompting。RIME 的出发点很直接：你无法在 prompt 里描述你还不知道的未来。指令能要求"总结精炼一点"，但没法描述"记住三周后会用到的那类信息"。所以 prompt 出来的记忆，最好情况也只是当前任务的摘要。

论文先做了个体检：在一个只有几条隐藏规则可发现的玩具环境里，prompted writer 连这种最简单的可挖掘结构都抓不住——上限问题不是措辞能解决的。更要命的是监督信号天然稀疏：第 3 个任务写下的记忆，可能要到第 15 个任务才兑现价值，中间隔着十几次写入的干扰。想用监督学习直接拟合"这条记忆写得好不好"，标签根本造不出来——这正是它选择 RL、把整条任务流的累计得分当优化目标的根本原因。

二、方法：两份奖励

任务流上交替两个操作：ACT（带记忆解题）和 WRITE（用本次经验更新记忆），优化目标是整条流的累计得分，不是单个任务。

Writer 拿 improvement reward：这条改写之后 K 个任务的平均分，减去之前 K 个任务的平均分。它直接度量"写入之后表现的斜率变化"，不看中间过程，绕开了 credit assignment。

Actor 在任务分之外拿一份探索奖励：LLM Judge 只读记忆的前后两个版本，按四条准则打 0~1 分：有没有从这次经历得出新发现、有没有修正记忆里已有的错误认知、有没有留下对完成后续任务具体可用的线索、是否与既有内容冗余——再合成一个 0~1 的总分，任何单项拉胯总分就上不去。

RACTt = rt + β · et，  et = Judge(Mt−1, Mt)

妙处在于：这是 novelty bonus，但 novelty 定义在写下来的东西上，不是访问过的状态上。经典 RL 里访问过的状态要手工设计表征才能判"新不新"，LLM 语境下"状态"天然有自然语言表示——所以这是第一个跨环境通用的实现，判分准则两个领域通用，只有描述环境的一句话不同。

防 reward hacking 靠训练动态而不是奖励函数：探索分只记在 actor 账上，writer 没有动机刷分；而记忆质量决定 actor 后续得分，两边互相牵制。反例是铁证：冻结 writer 单训 actor，actor 立刻学会刷探索分同时弃用记忆，增益从 +0.72 崩到 +0.02——防线不在损失函数里，在 co-training 的动态里。

作弊面本身也要压小。Raw LM 顺手就能想到的捷径不少：往环境里注入隐藏指令提前触发判分、跳过测试直接宣布完成、写一个永远返回成功的桩。RIME 的任务分直接取环境自带的测试输出，agent 改不了判分器；剩下能钻的空子，交给上面那对互相牵制的动态兜底。代价也要说清楚：每次 WRITE 都要过一遍 LLM judge，训练吞吐被它限死；这套奖励只在训练时存在，部署时只剩 actor 和它学出来的记忆。

三、结果

Codebase Adaptation：19 个未见仓库的 bug-fix 任务。Qwen3.5-4B 从 0.82 → 10.55，超过 GPT-5.4 和 Claude Opus 4.7。对照方法全被甩开：CoD −0.16、SkillRise +0.60。它们不是没训练，而是目标太短视——一个只度量当前任务的收益，一个拿任务分当记忆奖励——都测不出"这次写入让后面变好了多少"，学出来的自然是解题能力，不是写记忆的能力。

两个正交的观察：① 能力 ≠ 持续学习能力。Claude Opus 5.5 奖励全场最高但增益只有 +0.90，两个 Gemini 增益为负——带着历史跑比每个任务重置还差，说明把历史塞给强模型不等于它会用好历史。② Harness 救不了。Claude Code 增益 +0.73，Codex −0.80，比底层 GPT-5.4 裸跑还差。脚手架不会自动把历史经验变成更好的未来表现，该补的是 writer 的能力，不是上下文管理。

四、记忆里到底装了什么

两组诊断数据值得细看。Re-solve 动态：ACT 比例给到 100% 时，重做见过的任务 +13%，做新任务只有 +0.3%——它在吃老本；砍到 50% 后，重做 +9%、新任务 +1.4%，记忆开始向新任务迁移。同一过程里平均记忆体积从约 3KB 缩到 1.9KB：低价值条目（近乎满分的过易任务）被主动丢弃。"精炼"是学出来的行为，不是 prompt 要求出来的。Case study：Dafny-25 从 impossible 一路爬到 solved，中途记忆里出现过"避免空函数""先查 mod/div 前置条件"这类具体到操作层的教训——不是任务摘要，是能直接改变下一步动作的线索。

五、最狠的两个消融

① 训练 writer 但去掉探索奖励：增益变负，比无记忆裸跑还差。链条是：探索让轨迹携带新信息 → writer 有东西可学 → 记忆有用 → actor 愿意用记忆 → 信号干净。反转任何一环，整个循环反向运转。

② 训练数据是方法的一半：任务必须相关——同一仓库的 bug-fix 之间才有可迁移的教训；段必须够长——3+3 退化到单任务水平，6+6 才能学出稳定策略；还必须同时存在"机会"和"必要"——易→中→难排序，先用易任务学会环境语法，后面的难任务才既有写记忆的机会、又有用记忆的必要，中→易→难或纯随机都不行。三个环境的任务流总共 382 条，训练流只有 12 个任务，但在 26+ 任务的未见长流上增益仍在继续爬升——学到的是写记忆的手艺，不是背训练流的模式。

六、工程启示

  • 给记忆系统加 gain 指标：带记忆跑一遍、每任务重置跑一遍，差值才是记忆的真实价值。这个数完全可能是负的，而任务成功率曲线看不出来。
  • prompted writer 上限很低：连"只有几条隐藏规则"的理想玩具环境都抓不住，别指望 prompt 调优能救。
  • 部署侧没有 composer：探索奖励靠训练时的调度器主动安排"值得写"的机会，部署时用不了——部署侧的记忆质量，完全由训练侧建立的动态决定。
  • 复现 RIME 的硬门槛是数据：382 条任务流做 RL，个人 agent 场景没有这个量级。短期更现实的是借它的评测思想。
  • 带走一句话：训练会持续学习的 agent ＝ 同时训练 actor 和 writer 两条曲线并保持同步。任何一条单独优化，系统都会进死循环。
