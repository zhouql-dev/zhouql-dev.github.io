论文：VERA: Scaling Verifiable Environments for Agentic co-Evolution
链接：arxiv.org/abs/2610.05923 ｜ 代码：github.com/AutoMedBench/VERACode
一句话：把评测轨迹批量转成可验证、可重启的训练沙盒，再让模型权重和 harness 在归因驱动的交替轮次里协同进化，9B 反超最强单轴基线 10+ 分，27B 在办公域超过 Claude Opus 4.8。

一个被反复验证的判断：环境是瓶颈

让 Agent 从自己的尝试中变强——递归自我改进（RSI）——是 agentic AI 的终极野心。代码、办公自动化领域已经看到了雏形，但在长程研究型任务（比如医学研究：定位影像发现 → 分类 → 撰写报告，几十个相互依赖的步骤，一步错、步步错）上，这件事至今没有跑通。

这篇论文的出发点非常干脆：瓶颈不是学习算法，而是环境。当前的 Agent 训练环境有两条主流生产路线，都在长程任务上失效：手工构建的流水线只按最终结果打分，评测基准也是人工策划、只看 outcome。两者的共同缺陷是：环境提供不了阶段级的、经过验证的失败证据。自进化循环拿到的只有一个个孤立的分数，不知道错在哪一步、为什么错。

VERA（Verifiable Environments for Agentic co-Evolution）要做的事：把可验证环境规模化生产出来，再让 Agent 在上面进化。

Figure 1：VERA 通过可验证环境实现模型-harness 协同进化。上半部分：自动生成的 rubric、Agent Judge 工作区检查、容器回放，先验证环境再规模化；下半部分：归因模块读取阶段级评分与轨迹，产出模型报告与 harness 报告，两条更新轴交替推进。

Auto-Rubric：把轨迹变成可重启的沙盒

VERA 的关键洞察是：基准评测的轨迹本身就包含了可验证环境所需的一切——初始状态、工具交互、可观察的执行效果。Auto-Rubric 流水线把这些轨迹转成训练沙盒，分三步。

第一步，生成评分标准。一个编码 Agent 阅读任务描述、工具文档和执行日志，写出二元评分项（rubric）：每一项都是 {0, 1} 打分，考察动作参数是否合法、执行是否真的产生了效果、产物是否存在、输出质量是否达标。每一条都必须能从可观察证据中判定——rubric 既是任务的完成条件，也是证明完成所需的证据清单。

第二步，验证沙盒。每个候选环境要过两道关：可执行代码检查（工具/技能 schema、状态恢复、确定性输出），以及 Agent Judge（不止是 LLM-as-a-judge，它会真的去操作工作区，检查参数、执行效果、产物证据）。

可执行检查一旦失败，直接覆盖 Judge 的评分——这条规则是对抗 reward hacking 的关键设计。LLM Judge 会被说服、会看走眼，代码不会。

第三步，切段。论文把长工作流切成五个阶段：plan → setup → verify → execute → submit。阶段化沙盒会把每个阶段的起始状态恢复出来，配上对应的任务查询、交互历史和该阶段的 rubric，让每个阶段可以被单独练习、单独打分。另外还有端到端沙盒，保留完整工作流，用 LLM 代理模拟耗时的工具调用。两条线最后都要通过验证才能入库。

Figure 3：Auto-Rubric 让长工作流可重启、可验证。训练沙盒 = 验证过的环境 + 任务查询 + 恢复所需的交互历史；编码 Agent 从技能配置、工具文档和执行日志生成二元 rubric；轨迹切成 S1–S5 五个阶段，每阶段独立练习与打分；不过验证的环境进不了训练库。

协同进化循环：一次只动一个轴

环境就位后，VERA 的训练循环交替更新 Agent 的两个部分：模型权重和 harness（技能、工具、执行规则）。铁律是：训练模型时冻结 harness，改 harness 时冻结模型，rubric 和验证器在一轮内不动。这样任何性能变化都能归因到单一轴上——这是整个方法成立的前提。

每轮开始，先在开发任务上评估当前的"模型 + harness"组合，然后 LLM Attribution 读取阶段级评分和执行轨迹，产出两份报告：LLM Report 定位失败最集中的目标阶段（给模型训练用），Harness Report 列出缺失或误导性的流程（给 harness 编辑用）。证据来自 rubric，决策权在验证器。

模型轮：在阶段化和端到端沙盒里做新的尝试，用 rubric 得分作为奖励做全参数 GRPO，训练目标和课程跟随 Attribution 定位的目标阶段。

Harness 轮：增加、合并或删除技能，但每条编辑必须通过配对验证——同一个冻结模型、同一批任务、有/无这条编辑各跑一遍，只有编辑本身可能是差异来源。接受条件相当严格：改善目标阶段、端到端无回退、通过安全检查和自测、开发集 Overall 至少提升 5 个百分点，每轮最多接受三条编辑。

技能被频繁使用不构成它有效的证据，只有配对对比才算数——这句话值得所有做技能库的人贴在墙上。

结果：9B 反超单轴基线 10+ 分，27B 逼近前沿

用 Qwen3.5-9B 做骨干，在两个域上对比：AutoCoWorkBench（办公自动化长程任务）和 AutoMedBench（医学研究工作流）。

方法（Qwen3.5-9B）AutoCoWorkBench OverallAutoMedBench Overall
基座 + 默认 harness4.219.9
ADAS（harness 进化）20.755.5
GRPO（模型进化）5.836.3
OPD（on-policy 蒸馏）19.841.2
COS-PLAY（联合进化）19.926.4
VERA Agent（协同进化）31.069.1

消融实验证实：冻结任何一个轴，收益大约损失一半。模型和 harness 的贡献大致对等（CoWork 上），医学域里 harness 侧贡献更大。

27B 规模上更凶：VERA-CoWork-27B 达到 71.6，超过 Claude Opus 4.8（66.6），距 GPT-5.6-Sol（72.6）仅 1 分；VERA-Med-27B 达到 80.7，距 Claude Opus 4.8（81.9）仅 1.2 分，Agentic 分项 94.1 是全场最高。在未见过的 Automation-Bench 和 AgentClinic 上分别比基座提升 19.2 和 32.5 个百分点，迁移能力成立。

Figure 2：VERA 在 4B / 9B / 27B 各规模上都优于基座 Agent（a-b）；27B 在两个基准的 Overall 均列第一（c-d）；在 Automation-Bench 与 AgentClinic 两个未见过的基准上迁移提升 19.2 / 32.5 个百分点（e-f）。

一个值得注意的细节：能力保持 strongly 依赖骨干规模。4B 和 9B 的 Agent 在通用基准上大幅退化（4B 的 AIME 掉了将近 60 分），而 27B 不仅没退化，CoWork Agent 在 AIME、ALFWorld、GPQA-Diamond、IF-Bench 四项上全部提升（+10.0 / +3.8 / +7.7 / +1.8）。强骨干才能撑起自进化而不牺牲通用能力——这对"小模型也能 RSI"的乐观叙事是一记冷水。

自进化的真实成本：环境占一半

论文给出了一份罕见的 RSI 成本账单（医学研究流水线，估计替代成本约 24 万美元）：环境规模化与清洗占 54.7%，训练基础设施占 27.9%，验证、评判、归因等占 17.3%。而且协同进化要等环境准备完成约 75% 后才能启动。如果你想复现这条路，预算的大头不是 GPU，是环境工程。

为什么这篇论文值得认真读

第一，它把"可验证环境"从一个 RL 训练细节上升为一种可规模化的资产：9,000+ 个开源沙盒，每个都带 rubric、可执行检查和通过验证的保证。环境即护城河，这个判断在 Agent 竞争的下一阶段会反复应验。

第二，它给"模型和 harness 协同进化"这个新兴方向提供了目前最干净的归因框架。此前的联合进化系统（如 COS-PLAY）没有验证过的失败证据，每次改动只能看总分涨跌；VERA 用冻结-解冻纪律加上配对验证，让每一次改动都有明确的因果证据。

第三，工程上最容易被忽视但最重要的一条：可执行检查覆盖 Judge 评分。任何想在生产环境搭自进化循环的团队，这条规则都应该是第一原则。

对正在构建个人 Agent 系统（技能库、记忆、自主循环）的人来说，这篇论文提供了一个可以直接借鉴的元框架：你的 Agent 每次技能改动，是否也有一套"冻结模型 + 配对重跑 + 明确接受标准"的验证流程？没有的话，所谓 self-improving 只是随机游走。

三句话总结

1. 长程 Agent 自进化的瓶颈是环境：没有阶段级的可验证证据，进化循环就是盲人摸象。

2. VERA 用 Auto-Rubric 把评测轨迹批量转成可重启、可打分的沙盒，再用归因驱动的交替轮次协同进化模型权重和 harness，每次改动都过配对验证。

3. 9B 反超最强单轴基线 10+ 分；27B 在办公域超过 Claude Opus 4.8；但通用能力保持只在强骨干上成立，且环境工程占了总成本的一半。
