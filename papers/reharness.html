ReHarness：agent 的记忆不该只进不出

现有 harness 把经验写进去就再不复审，过时的反思会反复误导决策。ReHarness 给记忆状态补上一条「反向修订」通道——本质上是文本版的 BPTT。
arXiv:2610.12668  ·  MIT × Meta MRS Research × Yale  ·  原文 PDF

一句话

agent 记忆系统的真 bug 不是「记不住」，而是「记错了不认账」。ReHarness 在严格在线流式协议下，用自然语言反馈实现反向修订，让每条经验都带着「下次被用后回来修改我」的回收通道，九个 backbone×benchmark 组合里八个第一。

一、一个坑了两次的例子

论文开篇的排序例子，把问题讲得干净利落。agent 拿到任务：把 {3,7,4} 降序排列——答对，于是写下一条反思：「大的放前面」。下一个实例是升序 {2,9,5}，系统检索到那条反思照做，答错。它又写了一条新反思「小的放前面」——但旧的还躺在记忆库里。第三个实例升序 {3,7,4}，旧反思再次被检索出来，又错一次。

注意这里发生了什么：错误不仅持续，还在自我强化。过时、过度泛化的经验一旦写入状态库，会在后续检索中反复被激活，而系统没有任何机制回头去修改它。

二、Forward-only harness 的结构性缺陷

Mem0、ReasoningBank、DoT、ACE、GEPA-Online 这些方法，本质结构都一样：一个「记忆 agent」πM 在任务结束后把经验写进状态 ht，一个「决策 agent」πD 在新任务时检索相关经验来辅助决策。信息流是单向的——写和读都只往前走，状态只增不改。

这在连续学习（continual learning）里是致命的。因为学习协议本身非常严苛，论文称之为「严格在线流式」（strictly online streaming）：

×
不能 replay
每个实例只出现一次
×
不能验证集
没有留出的调参数据
×
不能梯度
模型只能走 API

三个「不可能」叠加，意味着学习信号只能是自然语言反馈——这正是 TextGrad / Reflexion 那条路线。ReHarness 的贡献，是把这条路线搬到了 harness 状态层面，并且第一次做成了闭环。

三、核心方法：读 → 修订 → 写

ReHarness 把 harness 从「有状态」升级为「递归」——在前向读/写之外，补一条反向修订通道。每个实例走三步：

  1. Forward Read（前向读）：检索 top-5 相关反思，喂给决策 agent πD，辅助它完成当前任务。
  2. Backward Revision（反向修订）：拿到本实例的轨迹 τt（含奖励）后，修订 agent πR 逐条重审刚才用过的反思——「这条经验当时该怎么写，才能避免这次的错误？」修订产物直接替换旧反思。
  3. Forward Write（前向写）：记忆 agent πM 对当前轨迹生成新反思，并且用刚修订完的旧反思作为示范，让新反思学会自带适用条件。

整个循环里最关键的设计是 grounding 约束：修订时，当前轨迹 τt 只能作为「反馈信号」，不能作为「内容素材」。新反思的事实必须锚定在它自己的源轨迹 τi 里，否则就变成把答案直接抄进记忆——这是作弊。

回到排序例子：「大的放前面」被修订成了「大的放前面，仅限降序时」。看清这一步的本质——修订做的不是纠正结论，而是补上适用条件，把一条无条件规则变成一条有条件规则。过度泛化的病根就在「无条件」，药方就是让经验显式携带自己的边界。

四、关键实验

评测横跨三个 benchmark——CL-Bench（角色扮演、代码库、SQLite、销售、频谱、poker 六类任务）、MemoryBench、MemoryArena，各配三个 backbone（Claude Opus 4.8 / GPT-5.5 / Gemini 3.7 Flash），共九个组合。

最反直觉的一点

「裸上下文」（raw context）——把历史轨迹直接塞进上下文，居然比 Mem0、ReasoningBank、ACE 这一票精心设计的结构化记忆方法都强。这和 CL-Bench 原论文的发现一致：结构化记忆方法大多打不过裸上下文。而 ReHarness 是少数真正打赢 raw context 的结构化方法——这说明「加结构」不是没用，是之前的结构没解决「经验会过时」这个核心矛盾。

还更省：token 账算得过来

Full Raw 的 token 消耗是 ReHarness 的 3.4 倍，Top-K Raw 也要 1.3 倍。原因是修订让反思变得紧凑、去掉了冗余，输入侧省下的钱覆盖了输出侧（修订 + 写）的开销。持续学习里「越用越长的上下文」是成本黑洞，ReHarness 反而把状态控制住了。

决定性验证：counterfactual replay

怎么证明「反向修订确实产出了更好的经验」？论文设计了一个漂亮的反事实实验：修订完成后，把修订后的状态拿回来重做刚刚那个实例。相当于「考完试，改了笔记，重新考一遍同一张卷子」。

五、修订到底改了什么：两个定性案例

案例 (a) ——修正早期过度泛化。在盲频谱监测里，agent 要从连续扫描中推断持续存在的发射台。τ2 之后，记忆 agent 过度泛化了证据，建议「填补大的静默间隙，报告看起来合理的额外信道」。但任务奖励的是与真实占用频谱的重合——漏报真发射台和编造假发射台都扣分。当这条反思在 τ3 被检索出来，决策 agent 照做、加了没观测到的发射台、拿了低奖励。用这个结果做反向反馈，修订 agent 把该假说标记为「推测性的」，改成「优先保留已确认的峰值，而非添加未确认的」。下一轮检索到修订版，奖励大幅回升。这是一个「在错误经验误导未来决策之前就把它掐掉」的例子。

案例 (b) ——分布漂移后翻新旧策略。数据库探索任务里，agent 要查询未知的 SQLite。τ2 时决策 agent 没检查价格列 prc 的 null 值，但记忆 agent 在早期流里反复使用后，固化出一条「评分值来自 prc」的反思。τ20 之后 CL-Bench 引入漂移：改了 schema、加了 prc_v2。旧反思在 τ23 被检索，决策 agent 只查 prc，而正确答案在 prc_v2。用这次失败做反馈，修订 agent 把规则改成「不要假设哪一列被评分」「枚举所有价格类列」。τ25 检索到修订版，两次查询就命中正确答案。这是分布漂移下「旧经验变负债」被及时清算的例子。

六、稳定性 vs 可塑性：漂移时刻的账

论文把归一化增益拆成两个维度：stability（稳定性）衡量漂移后第一个实例上的增益——此时还没有新分布的反馈可用，纯靠旧经验撑着；plasticity（可塑性）衡量漂移后的后续实例——方法已经能适应当前分布。

关键发现：Mem0、ReasoningBank、DoT、ACE、GEPA-Online 的平均 stability 增益全是负的。这意味着在分布漂移的那一刻，它们那些 forward-only 的记忆状态不是「帮不上忙」，而是净负债——过时经验主动把决策带偏。而 ReHarness 是唯一在两个维度上都拿最高平均增益的方法：修订让它既能在漂移后及时清算过时经验（plasticity），又不会把还有用的经验误杀（stability）。

热力图把这种动态看得更直观：漂移发生前（τ9 之前），对旧反思的修订量逐渐衰减，状态进入稳态；漂移一发生，修订量骤增，h10→h11 对 τ0、τ1 的旧反思做了大幅修订；随着流推进，修订又逐渐集中到跟漂移后分布相关的新近反思上。这是一种自组织的「漂移检测 + 定向重审」行为。

七、消融：两条通道都在干活

  • 去掉修订 agent：增益全面下滑——反向通道是收益主体。
  • 去掉「修订结果作为写反思的示范」：增益从 0.217 掉到 0.191。修订后的旧经验会「教」记忆 agent 写出更好的新反思，一鱼两吃：同一份修订产物既更新旧状态，又指导新知识的生成。
  • 检索条数 k 扫描：k=5 是甜点。更大的 k 反而引入不必要的修订和 reflection 漂移。

八、局限：诚实但关键

反向修订的成色，取决于下游奖励的诊断性。这是所有用 outcome 做学习信号的方法的共同宿命。
  • poker 任务失效：奖励和策略弱耦合（运气成分大），修订信号太噪，方法基本没增益。表里 poker 列 ReHarness 只有 0.009，是所有任务里最差的。
  • 存储开销：为了支持后续修订，必须保留原始轨迹 τi，内存成本高于纯摘要式方法。
  • 依赖强 LLM：修订质量高度依赖修订 agent 的判断力，弱模型上可能产出低质量修订。

九、工程意义：给记忆装一条回收通道

退一步看本质。RNN 早就证明过：只有前向传播的网络学不到东西，误差必须沿时间反传。harness 状态就是文本版的隐藏状态，而现有记忆系统全是 forward-only 的「无梯度网络」。ReHarness 做的事，是给 harness 状态补上文本版的 BPTT——只是反向传的不是梯度，是自然语言反馈。

这个类比不只是修辞。它预测了两件事，论文也都验证了：其一，反向通道缺失会导致「过时经验累积成负债」，对应 forward-only 方法负的 stability；其二，反向信号的诊断性决定学习上限，对应 poker 的失败。对一个正在设计 agent 系统的工程师来说，可直接落地的模式是：

可落地模式

记忆库里每条经验都应该带一条「被检索使用后，回来修订我」的回收通道，并且在写入时就用修订后的旧经验做示范——让新经验天生带着适用条件，而不是等它犯错了再补。只写不审的记忆，迟早变成噪声库。
