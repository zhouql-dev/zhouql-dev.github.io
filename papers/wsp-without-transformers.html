01反转的问题：让 LLM 自己定架构

Transformer 为什么长成 Transformer？因为每一层都是稠密矩阵，每个矩阵都能求导，GPU 的稠密乘法恰好跑得飞快——它伺候的是梯度下降。架构不是抽象的数学选择，而是优化器的仆人。

Weight-space programming（WSP）把这件事整个换掉：权重不再由优化器从数据中训练出来，而由一个大语言模型一行一行写出来。11 月初解读的第一版已经证明，LLM 手写的权重能打赢从零训练的小模型——但那版里架构是给定的。这篇续作只问一件事：如果连架构也交给 LLM 自己定，它还会选 Transformer 吗？

实验设置极简。任务：ARC-Easy 与 ARC-Challenge 合并的 3,530 道四选一科学题。每个 writer（Claude Opus 5.5、GPT-6.1 Sol、GPT-6 Astra）只看到 10 道标注样例（两边各五道），看不到任何其他 ARC 数据、看不到测试分数，在沙盒里交付三样东西：架构文件、构建脚本、明文知识文件。宿主把知识文件编译成张量、跑测试。

两个比较 regime：固定架构（LLM 往 15 个已发布架构的随机初始化上写权重，或往指定的两层 Transformer 上写）和自由设计（结构、构建脚本、知识文件全部自制）。第三个维度是世代替换：从第二代起，writer 还能看到父模型代码和父模型的验证精度，其余分数一律不外传（见 Figure 5）。

02三个 LLM 造了什么：收敛到关联记忆

放开架构后，三个前沿模型没有一家造 Transformer。它们收敛到了同一个东西，而这个结构 1960 年代就有了：关联记忆（associative memory）。

流程完全一致：先把领域知识写成明文句子；再写一个构建脚本，把每句话编译成稀疏表的一行；最后用一个固定程序读表——把问题和每个选项里的概念拿去匹配事实行，选总分最高的选项作答。Claude 的事实表最终 4,288 行、29,502 个非零值。没有 attention，没有 MLP，没有稠密嵌入。

Claude 在运行日志里留下两句设计理由，是全篇最动人的证据：

"Without training, the only way to get knowledge into the model is to write it, and short declarative facts are the cheapest form to write and check." 没有训练，把知识放进模型的唯一办法就是写它；而简短的事实陈述是最便宜、最容易检查的写入形式。
"A sparse retrieval model makes every number traceable to a sentence I wrote." 稀疏检索模型让每个数字都能追溯到我写的一句话。

Figure 2 画出了这次结构替换：堆叠的稠密层让位给"读一次就完事"的写出来的表。彩色块是 LLM 写的权重，白色块是固定操作；q 是问题的概念向量，oc 是选项概念。

Figure 6 更有意思：三个 LLM 造的第一代模型结构同类，差别只在"一行怎么切"——每一栏从下往上读，都引用了它自己写的一行。同一个物种，三种方言。

03两条可写性公理：可追溯与局部编辑

LLM 为什么集体绕开 Transformer？论文给出两条"可写性公理"，并设计实验逐个验证。

公理一：可追溯——每条预测能追到具体写入的那一行

做法：每个选项只保留分数最高的那条事实行，其余全丢，看准确率掉多少。全模型 50.8%，只留单行 49.1%——预测几乎完全由每条"最好的事实"决定。同一测试套在 GPT writer 上同样是 1 分左右的差。

Table 4 顺带做了两组破坏实验：禁止把"练习题"写进表（防记忆训练集），掉约 1 分；完全禁止事实行（只剩规则和模式），掉约 5 分——而且非零值反而多出 100 倍以上（84M–392M）。知识确实编码在事实行里，其他都是陪衬。

公理二：局部编辑——改一行只影响依赖它的预测

做法：随机删一行重建模型，与未删模型对比全部 3,530 道测试题的答案变化。表模型平均只改变 0.5–1.8 个答案；写进 Transformer 平均改变 4.8 个；而第二个实现的构建脚本从同一个随机流里抽所有向量码，删一行几乎动全部权重、平均改变 1,350.7 个答案（38% 的题）。同一个架构，两种实现，可编辑性天差地别——这把"架构选择"具体化成了"构建脚本怎么写"。

内容还是结构？——最狠的对照

另一种解释是：准确率来自 LLM 写下的事实本身，结构无所谓。那就让 LLM 把同样的内容写进 Transformer，再拿 BM25 对它自己写的文本做一次朴素关键词搜索，看谁高。

Claude 写的六个两层 Transformer 全部输给 BM25，平均低 8.0 分；表模型全部高于 BM25。GPT 两个 writer 同向：11 个写的 Transformer 里 8 个输 BM25，16 个表模型里 13 个赢。同一份知识，装进稠密层就变笨。

04我们的设计：哈希直址的关联记忆

三个 LLM 的设计有个共同硬伤：为回答一道题，要给表里每条事实都打分。事实越多单题越慢，而且每题发射大量 GPU kernel。46 个 LLM 设计模型里只有一个快过同尺寸 Transformer，中位数慢 9.4 倍（下一节细说）。

作者在"保留写出来的表"和"读得快"之间搭了座桥：概念配对不再扫描，改用哈希直址寻址：

h(a, b) = (a·p + b) mod H a、b 是两个概念的编码，p 取素数，H 为表大小。配对表从百万行无损折叠到 H = 65,536 行——1,048,576 行时 49.6%，65,536 行时 49.8%，几乎不掉分。

考题进来，四个概念两两配对成六对，每题固定只读 120 行配对表，再做一次与概念表的乘积：

S(c) = Σc′ ∈ 召回 wpair(c′) · wconcept(c′, c) 配对表行里存着"共现概念 + 权重"，与概念表 A 的值相乘累加得到选项得分。

Figure 3 是一道真题的完整链路：adaptation 与 fly 配对命中一行，召回 hollow 和 bones；与概念表相乘后，hollow bones 得分 52.1，次高选项只有 15.8（2.2 × 9.1 + 3.2 × 10.1 = 52.1）。就算完全不用配对表，概念表 A 单独也能把正确答案排第一（16.9 对 11.8）。

效果：非零值涨到十亿量级，单题推理时间不变；3,530 题在 RTX 3090 上 0.018 秒跑完，比同尺寸 Transformer 快 7×（gen1）到 17×（gen5），准确率只让约 3 个点。

边界也说清楚了：它的时间随概念数涨——稠密概念表在约 1.5 万到 3.2 万概念以内保持优势，改用行列表能撑到约 10 万。

06主结果：54.4%，用别人的 1/1800 参数

Table 3 是主结果，全量收录。几个读法：

自由设计全面赢固定架构。同一个 writer，自由设计比"往 15 个已发布架构上写"高 7–12 分，参数还少三个数量级。最强 lineage（Claude gen5）54.4%，参数量只有它自己写出的最准已发布架构的约 1/1800。

07边界实验：ARC 之外还剩多少

论文没停在四选一上，做了四组扩张。

同分布迁移。写好的模型原样跑：SciQ 47.7%（gen1）→50.1%（gen5），离 ARC 差不到 4 分；OpenBookQA 30–36%；MMLU 掉到随机水平（约 25%）。模式和"Claude 写的是小学科学"一致——writer 写了什么，模型就会什么。

一个模型 multitask。给 LLM 十道 ARC、十道 MMLU、十道 MathBench 样例 + 五段 SQuAD 段落 + 五条 CNN/DailyMail 摘要，它造出共享词表、每类任务一个 reader 的模型——事实表 + 考试规则 + 段落抽取器 + 首句复制器。

图像。CIFAR-10 原始像素上写出的网络只有 21–28%——像素上的权重没有 writer 能叫出名字的含义。但换成预训练 DINOv2 的语义 token，零图像标注能到 96.1%：writer 对每个 token 看五张含它的训练图，命名其中的物体，按 token 统计类别。注意这是 encoder 的功劳——同样的 token 上梯度下降也要约 100 个标注才追平。

文本分类。AG News 零数据写出来约 84%，梯度下降从随机初始化要用几千条标注才追平。更实用的玩法是 warm-start：拿写出的网络初始化，再用 100 条标注做梯度下降，84.7%；同标注量从随机初始化只有 63.6%。写的不是终点，是更好的起点。

预训练权重覆写。30 次覆写里 19 次的目标是接近随机的 checkpoint；UltraBERT / ModernBERT 这种 43–64% 的 checkpoint 覆写后会掉点；而 72.3% 以上的 checkpoint 一次都没被覆写过（28 个 run，每次至多改 0.07% 参数）。LLM 会看父模型精度决定动不动手——这本身是个有意思的安全信号。

08批判与局限

论文自己列了五条 limitation，前两条的分量最重：

检索不是推理。所有表模型、关联记忆模型都在"回忆 LLM 写下的事实"：不跨步组合，不生成新推理。ARC-Challenge 长期卡在 38% 左右而 Easy 到 63%，MMLU 掷骰子。所谓"生成"是读出存储的答案。

结论范围限定得很窄。"不需要 Transformer"只对"现在这代 LLM、从随机初始化写权重、不跑数据"成立。作者自己立了三道验收对照：对写出的文本单独跑 BM25、说清实写权重数（非零值）、换 benchmark 验证迁移。以后谁再说"某结构更适合 WSP"，都得过这三关。

速度优势有概念数上限（稠密表 1.5 万–3.2 万，行列表约 10 万）；lookup 硬件全是借来的论证——实测只在 RTX 3090 这种稠密乘法硬件上做过，近存计算、FPGA、内容寻址内存都还只是引用；低标签领域（医疗、个性化）没做实验，只有 AG News 的代理证据。

我的三条批判：

一，结构熟悉度混淆没有被排除。三个 LLM 都选检索表，可能因为训练语料里 retrieval baseline 太常见——它们不是"推导出最优"，而是"最熟悉"。BM25 对照堵住了"纯粹是内容"的解释，没堵住"纯粹是熟悉"。

二，账本没人维护。4,288 行还好说；真到十亿行非零值，事实冲突、过期、去重谁来做？可追溯性把调试成本降下来了，但把一个数据治理问题引进来了。

三，评测全是四选一或抽句子。这类任务里"检索 = 解题"，表结构天然占便宜；推理型任务上它连门都没进。

09结语：架构是写入方式的仆人

这篇论文真正的贡献不是"表打败 Transformer"，而是提醒我们：架构从来不是抽象的数学选择，它是写入方式的仆人。SGD 时代长出卷积，GPU 时代长出 Transformer（Hooker 2021 的共进化论证），现在第三种写入方式出现了——LLM writer——它选了可追溯、可局部编辑的哈希表。作者顺势预言下一个配套硬件：lookup 友好的 FPGA、近存计算、内容寻址内存——大规模稀疏负载上，哈希化的 CPU 执行早就跑赢过 GPU。

和两周前读的 Weight-Space Reading 连线：WSR 管"写了之后怎么知道写对"（读权重、找错误），这篇管"怎么写才能写得对"——答案是先保证每个权重有名字。两篇共享同一条公理：weights as inspectable knowledge。

再往上一层看，这是一条新的神经符号路线：不是"神经 + 符号"的混合体，而是用纯神经硬件（LLM 写入）跑纯符号结构（表 + 规则 + 读取程序）。可追溯性和局部编辑把软件工程的可调试性还给了神经网络。

留一个问题当 LLM 既能设计架构、又能写入权重、还能跨世代给自己评分（作者展望的 rubric-guided 自动搜索），"训练"这个词还剩多少原意？
