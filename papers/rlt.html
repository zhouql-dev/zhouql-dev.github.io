Recurrent Looped Transformer
把"思考深度"从架构常量变成序列变量

潜推理 × 模型-硬件协同设计 × 模型-RL 算法协同设计——一份零实验但把三个真问题讲透的架构规格书
Yifan Zhang · 技术报告 · 2026-09-12 发布
一句话：RLT 让 decoder 隐状态跨 token 递归传递且在 prompt/response 边界永不重置——t 个 token 后计算路径深达 48t 层，"推理深度"第一次成为随序列增长的变量而非架构常数。附带一份对 RL 社区相当锋利的 replay 契约。

一个反直觉的主张

标准 Transformer 有个隐含假设：每个 token 的计算深度是架构常数。不管上下文多长、问题多难，每个 token 都走过同样的 N 层。要"想得更深"，要么加层，要么生成更长的思维链——前者是静态的，后者把推理外包给了 token 空间。

RLT 的出发点是：深度应该随序列增长。它让 decoder 的最终隐状态跨 token 传递——每处理一个 token，隐状态就在 decoder 里再穿一遍。t 个 token 之后，计算路径已经穿过 t × LD 个 decoder 块，而每 token 的执行块数保持固定。"无限深度"指的就是这个：深度上限不存在于架构里，而是被序列本身定义。

这和 Geiping 等人的 recurrent-depth（Huginn）是互补的两种 loop：Huginn 在 token 内部迭代同一个块（同一个问题想 32 轮），RLT 在 token 之间传递状态（思路跨 token 累积）。前者是"单步想久一点"，后者是"记忆越滚越深"。

结构：并行感知 + 串行思考

RLT 拆成两条腿。因果 encoder 对全部已知 token 做标准并行因果编码，产出全局 KV memory——这是 GPU 可以大批量并行吃掉的部分。递归 decoder 则严格串行：每一步把当前 token 的 encoder 表示 et 与上一步最终隐状态 st−1 做门控融合，然后过一遍 decoder（每层先滑窗注意力 SWA 读自己的局部缓存，再 cross-attention 读 encoder 全局 memory）。

Ht = (st, CDt) = Dφ( Merge(et, st−1) ; M≤t, CDt−1, t )

完整状态从 prompt 第一个 token 一路带到 response 最后一个 token，在边界不重置。这个分工很有"双系统"的味道：encoder 是 System 1（快速并行感知），decoder 是 System 2（慢速串行状态演化）。做视频流式理解的人会觉得眼熟——帧级特征并行提、状态逐帧递归推，本来就是流式感知的经典结构，RLT 把它做成了语言模型主干。参考配置下 encoder/decoder 共享 attention 与 FFN 权重（各 48 层，共 96 次逻辑块求值/token），decoder 块额外带 cross-attention，所以两次逻辑 pass 的 FLOPs 并不相等。

同序列、同参数下，移动 prompt/response 切分点不改变条件分布（Proposition 3.1，对固定 token 序列的数学等价）——这是后面 RL replay 契约的基石。

最锋利的部分：RL replay 契约

这份报告最值钱的不是架构，是 5.3 节。现在的 RL 流程里藏着一个结构性裂缝：同一个序列，采样时和训练时的计算方式不一样。采样时 prompt 走并行 prefill、response 逐步生成；trainer 重算 log-prob 时，如果任何带状态的组件在两个阶段不一致，你算出的"当前策略 log-prob"对应的根本不是采样时的那个策略。标准 Transformer 因 prefill/decode 数学等价而侥幸躲过；任何带 memory 的架构都会撞上。

RLT 给出的契约就三条：

① 预训练、SFT、采样、replay 用同一个状态转移函数——边界在策略定义里不存在；
② 权重每次更新后，从序列起点精确重建全部状态（encoder KV、递归输出、每层 SWA 缓存）——旧隐状态一律作废；
③ 采样时的 behavior log-prob 保留作重要性比率分母——它记录的是动作当时真实的采样分布，不随参数更新而变。

报告还顺手补了一刀：top-k / top-p 采样会破坏重要性采样的支持覆盖条件——被截断的 token 在目标分布里有概率质量、在行为分布里没有，ratios 数学上不成立。要做可信的 off-policy 修正，behavior log-prob 必须带温度、截断、重归一化的完整信息。对所有做 agent RL 的人都是提醒：你手里那个 ratio 可能从来没有无偏过。

硬件协同设计：围绕串行核的并行

RLT 不回避递归的代价，而是把并行的机会摆在递归核周围：encoder 的 token 级批量 kernel、跨独立序列 batch 就绪的 decoder 更新（每行保持自身状态序，列共享批量 kernel）、不可变 encoder KV 的驻留复用、全 BPTT 下的激活检查点。作者明确不宣称任何实测加速，也不假设非线性 decoder 存在精确的并行 scan。

工程代价：作者把丑话说在前面

这份报告罕见地诚实——通篇反复声明"零实测结果"。代价是明确的：

维度代价 / 现状
Prefill 延迟encoder 可并行，decoder 必须从首个 token 串行递归到最后一个。长 prompt 首 token 延迟显著劣于标准 Transformer。YOCO / DeepSeek-V4.1-Flash 式的 prefill early exit 路线被明确放弃——拿延迟换状态完整性。
训练全 BPTT，梯度穿过整条 T 步递归链；内存靠激活检查点换。梯度消失/爆炸与状态饱和完全未验证。gated merge 的反馈尺度 α，作者自称"候选初始化，不是已验证的稳定性配方"。
KV 存储encoder 全局 KV 随序列线性增长；decoder SWA 部分有界（每层至多 W−1 条）。但 cross-attention 每步仍要扫全部 encoder memory，注意力计算量照样随上下文涨。
推理增益结构深度 ≠ 有效推理。门控与投影可能压制长路径贡献——"结构上的深度本身不构成推理保证"，作者原话。

在相关工作里的坐标

路线代表与 RLT 的差别
encoder 记忆复用YOCO (2024)、DeepSeek-V4.1-Flash (2026)它们跳过 prompt 上的 decoder 计算（prefill early exit）；RLT 保留全 prompt 递归，状态完整但更贵。
时间反馈Feedback Transformer (2020)、Recurrent Transformer (2026)反馈位置不同：RT 是各层自身输出做持久 KV；RLT 把上一层 token 的最终输出送进下一 token 的输入。
深度复用 / 潜推理Universal Transformer (2018)、Huginn (2025)它们在 token 内迭代（单步想久）；RLT 状态跨 token 推进（记忆滚深）。
⚑ 对抗式审查——最可能翻车的点① 零实验：没有基线、没有 loss 曲线、连玩具实验都没有，48+48 只是纸面参考配置；② 串行 prefill 的延迟代价在实际服务场景可能直接不可接受，"用状态完整性换首 token 延迟"这个 trade 在对话产品里多半不划算；③ 全 BPTT 过长序列的显存与稳定性是 RLHF 社区反复碰壁的老问题，报告只有一句"用激活检查点换"；④ replay 契约虽然定义干净，但每次权重更新后全量重建状态的算力开销在真实 RL 训练里可能贵到无法落地；⑤ "无限深度带来推理能力"目前只是结构可能性——Huginn 已经证明这类结构要专门的训练目标才能激活路径。

我的判断

把它当宣言 + RFC 读，价值很高：它把"推理深度应该是序列的函数"这个直觉做成了可执行的架构定义，更把"策略 = 权重 × 执行方式"这个 RL 可信性问题摆上台面——那份 replay 契约对所有带 memory 的架构都适用，不限于 RLT 本身。把它当可复现的研究结果读，还不行。一句话总结：这是一份把三个真问题（潜推理的架构化、RL replay 一致性、递归模型的硬件执行）定义得非常清楚的规格书，实现和验证留给了社区——或者留给作者自己，我猜他会一路做下去。
