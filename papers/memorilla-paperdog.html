16 个 token，凭什么赢过 6300 个 token 的上下文？

斯坦福等机构给冻结的大模型装了一种「软记忆」：不往上下文里塞文本，而是把记忆直接注入模型的嵌入空间。8 个 benchmark 平均分第一，5 个单项第一。

同一句提问，四种系统的回答。Memorilla 用上了「缺铁性贫血」这段从未在本次对话中出现的记忆

PersonaMem-v2 里有一道题，用户问：白天想补充能量，吃什么好？

只看这句话，答案无非全谷物、香蕉、坚果。但 Memorilla 的回答开头是：「考虑到你有缺铁性贫血的病史，建议多摄入富含铁的食物……」（论文图 6 的示意案例）

关键在于，「缺铁性贫血」这个词从没出现在这次对话里。它是用户更早某次对话里提过一嘴的。字面上，新问题和那条旧记录没有任何词重合，余弦相似度检索也就找不到它。

记忆系统要处理的，就是这种「问题里没有、历史里有」的缺口。

一、三类做法

现有做法大致三类，最常被拿来对比的是前两类。

检索派：Mem0、A-MEM 把历史整理成摘要或结构化条目，MemoRAG 用压缩过的全局记忆引导检索。它们最后都要把选中的文本塞回上下文。局限落在「选」这个动作上：选漏了模型看不到，选多了上下文爆掉。

隐空间派：把文档压成几个 soft token 直接喂进嵌入空间，不经过文本。早期方法压缩时不看问题，同一批 token 要服务所有 query；xRAG 引入了 query 相关性，但只压一篇检索到的文档。

第三类存的是模型的隐状态或 KV cache，记忆和特定模型绑死，换模型就失效。

Memorilla 想补的是中间这块：从整个文档集合里，为当前这个 query 抽出恰好 K 个 token，放进冻结 LLM 的输入嵌入空间。

二、它怎么做的

Memorilla 架构：冻结的编码器把文档编码一次，可训练的记忆模块按 query 读出 K 个 latent，投影进 LLM 的嵌入空间

先说清 soft token 是什么。 它不是一个字，也不是 16 个字的缩写。它是 16 个和词嵌入同维度的向量，直接铺在输入序列最前面。模型照常做自注意力，一层都没改；「冻结」指的是那 80 亿参数一律不动。

编码一次。 冻结的 Qwen3-Embedding-4B 把每个文档块编码成向量，存进持久化记忆库。与 query 无关，只算一次，只有新增或改动的文档需要重编码。这一步几乎不额外花钱——它和稠密检索索引用的是同一份嵌入。

按 query 读。 训练一个 1.94 亿参数的记忆模块。16 个可学习的 slot 先对 query 做 cross-attention，各自带上问题信息、又保持彼此不同；再用 Perceiver 式的 cross-attention 扫一遍整个记忆库；最后投影到 LLM 的嵌入维度。这不是 top-k 选择，是对全部文档的一次连续读取。

注入。 16 行向量和问题文本的嵌入拼成 [m₁…m₁₆ ; Pq]，送进冻结的 Qwen3-8B。

可以这么想：检索是把原始材料复印几页递过去；Memorilla 递的是一张按问题写好的便条，不复述原文，但知道该带上哪条旧信息。

训练走三阶段：198 万条维基复述 → 134 万条阅读理解、开放问答、摘要的混合数据 → 在 8 个评测 benchmark 的训练集上多任务微调。损失只算答案位置。

三、数字

八项 benchmark 平均分 vs. 输入 token 数（对数轴）。Memorilla 在 16 个记忆 token 处位于帕累托前沿的最高点

横轴是喂给模型的文档 token 数（对数），纵轴是 8 个 benchmark 平均分。Memorilla 落在帕累托前沿的最高点：49.68 分，16 个记忆 token。

这里的 49.68 是 8 个主指标（Accuracy、EM、ROUGE-L 等）的等权平均，不是统一量表，看趋势可以，别当「准确率」读。

对照（后三项由 Table 11 的八个主指标算出）：full context 45.4 分，文档 token 数是它的 394 倍，几何平均约 6300 个；MemoRAG 47.5，RAG-50 46.2，闭卷 34.1。

有一点得说清楚：394 是八个 benchmark 的几何平均；后面这几个数都是对 full context 的，不是对最强 baseline——

  • FactKG 84.33%，full context 80.43%，MemoRAG 80.38%。对 full context 是 108 倍，对 MemoRAG 只有 36 倍，分差 3.95 个百分点。
  • LaMP-4 18.15 ROUGE-L，full context 14.21，474 倍；对最强 baseline xRAG 约 14 倍，分差 2.05。
  • TriviaQA 57.00 EM，full context 52.60，743 倍；对 MemoRAG 是 19 倍，EM 只高 0.40。

压缩率最大的那几处，往往不是分差最大的那几处。

延迟方面：512 篇文档在单张 H100 上 0.74 秒对 19.9 秒。解码占大头，所以集合越大优势越明显，小集合上不一定。

论文里最反直觉的一句是：full context 不是上界。21 个指标里 Memorilla 赢了 20 个。但别读成「长上下文没用」——full context 在 8 个 benchmark 上都远好于闭卷，只是低于 Memorilla 和 RAG-50。

四、它到底学到了什么

更有意思的是作者对分数的拆解。

NarrativeQA 按问句首词分类：why 类领先 RAG-50 4.91，how 类领先 7.02；反过来 who 类落后 3.45，which 类落后 2.93，单位都是 ROUGE-L。作者的解释是，压缩保留全局结构、丢掉字面 token，所以因果推理占优、抠人名吃亏。他们同时提醒，问句类型和答案长度、实体频率是混在一起的，不能只归因于压缩。

FactKG 按实体数拆：实体从 1 个到 4 个以上，Memorilla 对 RAG-50 的领先从 +4.23 个百分点涨到 +7.59。同时 RAG-50 在需要组合 4 个事实的题上从 78.73 掉到 51.75，Memorilla 一直稳在 80–89。这里要留个余地：73.5% 的 FactKG claim 超过 50 个 chunk，RAG-50 的下跌有多少是「没检索到证据」、有多少是「推理失败」，论文没有拆开。

互补性：FactKG 上 15.9% 的题只有 Memorilla 答对，10.0% 只有 RAG-50 答对；PMv2 是 27.1% 对 9.2%。两边答对的题并不重合，作者因此把「latent memory + 文本检索」的混合系统列为下一步。

五、该泼的冷水

PubMedQA 输得很难看。 59.00%，LLMLingua-2 是 69.00%，另外四个方法（含 full context）都在 67。一个解释是：这道题四篇摘要一共 324 个 token，本来就没多少可压。不过边界不只看集合大小——LaMP-7 只有 18 篇、459 个 token，Memorilla 仍以 48.37 领先 full context 的 43.71。更可能的分界是：任务是否依赖逐字事实。

8 个 benchmark 只拿了 5 个第一。 按主指标，NarrativeQA 和 PV4 第二；但 NarrativeQA 的 F1 其实是第一，PV4 的 hard 子集则落到第三、第四。PV4 还是作者自建的 benchmark，persona 和对话由 GPT-5 系列生成，用自家数据验证自家方法，说服力要打折。

训练条件不对等，这点最需要读者注意。 作者在方法小节写得很清楚：第 3 阶段在 8 个 benchmark 训练集上多任务微调，其中 6 个共用一个 checkpoint，PersonaMem-v2 和 PersonalizationV4 各做了一轮 benchmark 专属微调。问题不在隐瞒，在于比较——Memorilla 用了 198 万加 134 万条通用样本，再加 8 个评测域的训练集；xRAG 也在各 benchmark 训练集上训过；Mem0、MemoRAG、RAG 则是 training-free。训练量差着量级，分数差不能全记在架构头上。

六、更有意思的那一半

前面都是有监督、文档集固定的场景。第六节换了个设定：智能体在 TextWorld 里，一局最多 65 个房间、50 步，每回合结束后把这一回合存成新文档，K 降到 8。这里记忆不是替代文本，而是补充——两个条件下完整历史都还在上下文里。

只训记忆模块，用 GRPO 加环境奖励。结果 avg@3 从 0.186 提到 0.242，pass@3 从 0.250 提到 0.375。

TextWorld：只训练记忆模块，avg@3 从 0.186 提到 0.242；未经训练的记忆模块（15.3）反而低于纯 ICL

真正有意思的是那个对照：未经训练的记忆模块，avg@3 只有 0.153，比把完整历史塞进上下文的 ICL（0.186）还低。所以提升不是「多喂了几个 token」带来的，是学出来的。

行为上最大的变化不是解谜率，而是终止。ICL 有 71% 的 rollout 把 4096 token 预算烧光，Memorilla 是 58%——两者读的是同一段轨迹文本。看轨迹看得出，记忆帮它跳出了在已探索房间之间打转的循环。

TextWorld 这组结果的意义不在分数，而在一个更一般的问题：不更新模型权重，只训练一个「读记忆」的接口，也能改变智能体的行为。

收尾

论文配了一只戴眼镜、托腮看书的大猩猩（读图所得）。Memory 加 Gorilla，就是 Memorilla。

它真正问的是：记忆该以什么形式进入模型？文本派认为读懂原文最好，但选错了就没救；隐空间派认为该学的都进了向量，但字面丢了。这篇论文的选择是全部走 latent；「结构压进向量、字面留给检索」是作者提出的下一步混合方案，不是它已经做到的事。

如果「记住」指把信息写进权重，那它没有；如果指「需要时能把相关信息取回来并影响回答」，那它做到了——只是取回的不是原话，而是压缩后的语义。
