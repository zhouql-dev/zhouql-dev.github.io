不开口的判官：Stanford 把 Agent 的“系统一”做成了点积

2026-09-26 · 解读《Contrastive Language Models: A System One Model for Fast and Generalizable Decision-Making》(Kwok et al.) · Stanford（Ré 组）

昨天还在拆解 JEV 级联——小判官置信度不够才升级 GPT-6，省一半的钱。今天斯坦福 Ré 组直接把问题往前推了一步：为什么判官要“读”你的问题？决策这件事，可能根本不需要生成文字。他们发布了 CLM-8B（Contrastive Language Model），一个不说话的模型：给它当前状态和一组候选动作，它返回的只有概率。背景是 9 月 15 日 TypeSafe AI 发布闭源“系统一”模型 Jev，九天后开源世界就给出了对标答案——零样本打平、最快快 9 倍，verifier 场景微调后直接双 SOTA。

决策不是生成

Agent 循环里的绝大多数调用，本质是同一件事：从 N 个候选里选一个。工具路由是选工具，best-of-N 是选答案，typed decision 是选标签，连“这个状态紧急吗”都只是二选一。现在的做法是让 LLM 自回归生成一段理由再解析——每一个 token 都在重新计算“我是谁、上下文是什么”，而真正需要的只是一个排序。

CLM 把决策还原成它本来的样子：匹配问题。训练一个状态编码器和一个动作编码器，用双向 InfoNCE 损失——正确的状态-动作对在表示空间里拉近，错误的推远。推理时算点积、过 softmax，概率就是答案。这不是新发明，CLIP 对图文干的是同一件事；新的是有人把它端端正正做成了 Agent 的决策接口。

架构上的克制值得一提：Qwen3-8B 主干整个冻结，只训练两个约 20M 参数的投影头，整个“决策层”就 75MB。分工清晰——理解和编码是通用能力，冻结一次到处用；状态和动作“什么算相关”是任务知识，换头就行。

真正值钱的是解耦

模型本身不是重点，系统设计才是。Agent 循环里有个不对称性：状态每一步都在变，动作集基本不变——你的工具列表、候选答案、选项集合，整个会话里就那几样。CLM 把状态和动作的编码完全拆开，动作向量算一次、缓存起来反复点积。这和 vLLM 留 KV cache 显存板是同一个思路，只不过缓存的是决策而不是注意力。

收益随候选数量放大：3 个动作时重访状态从 1.7ms 降到 0.6ms；1000 个候选时比 Jev 快 13 倍。T-Rex 小游戏最极端——动作在状态间高度重复，16.5ms 对 149.8ms，9 倍差距全从缓存里来。

API 也值得注意：三种题型（Noul 判断真假、Choice 选项分布、Score 有序量表），与 TypeSafe 的接口直接兼容，为 Jev 写的请求原样重放。Agent 的“反射弧”第一次有了跨厂商的可替换标准——这是品类成立的标志，不只是单个模型。

训练配方：先广后难

三段式。预训练用 6000 万 Nemotron 问答对，问题当状态、答案当动作；中期训练加 3000 万 Gemini 2.5 Flash-Lite 合成的硬负例——语义相似但错误，专治“差不多”；后训练用 100 万条 agent 轨迹，掺 40% 通用数据回放防止灾难遗忘。

消融实验最有意思的发现：硬负例不能从头练。一开始就上难负例，精度冲到 62.4% 就过拟合；先用普通问答把表示空间铺开，再短程加练难负例，冲到 69.2%。这几乎是教育学的结论——先通识后专业，没有通识底的专才全是偏科。另一个实用细节：去掉后训练里的通用回放，通用评测立刻掉分，agent 轨迹再专也不能完全替代通识。

verifier 对决：Jev 判官成绩低于 pass@1（选过不如随机抽），CLM 微调头双刷新 SOTA，快 4.1–5.7 倍。

但 verifier 场景翻盘了。让 Opus 5 生成 4 个 DeepSWE 候选解、Fable 5 生成 5 个 Terminal-Bench 候选解，CLM 和 Jev 当裁判挑最好的：轻量微调后的 CLM 拿到 81.6% 和 87.6%，双双刷新 SOTA，延迟 79ms 对 449ms、32ms 对 131ms。更打脸的是 Jev 当裁判的成绩——低于 pass@1 基线，意思是闭源判官挑过的还不如随机抽一个。长程任务上，昂贵的生成式判官不仅慢，还不可靠。

边界在哪

论文（博客）自己的克制同样值得注意。CLM 只能在你给的候选里选——候选集的质量和覆盖是 agent 设计的问题，判官再快也救不了烂选项。输出的概率是相对当前候选集的，不是校准的绝对概率，跨请求比大小没有意义。另外整个头绑死 Qwen3-8B 加 last-token pooling 的配置，换编码器就得重训。

为什么值得看

这篇工作真正的贡献不是 8B 模型，而是把“决策”从 LLM 的本职工作里剥离了出去。生成式推理留给真正需要思考的时刻，机械选择交给点积——昨天 JEV 级联解决的是“判官多贵”，今天 CLM 解决的是“判官多快”，两块拼图正在拼成同一张蓝图：Agent 的认知分层。加上官方给出的 scaling law——encoder 越大收益最强，投影头大小随训练 token 数近似线性增长（N* ∝ D^1.02）——这是个还能继续 scale 的品类，35B 多模态版已经在 10 月的路上。

对做长时程系统的人，最值得偷走的不是模型，是那个不对称性：状态高频变、动作集低频变。任何“每步都要重新理解一遍选项”的 agent 循环，都有一块现成的缓存红利没有吃。

系统二负责想，系统一负责选。Transformer 管开口，点积管拍板。
