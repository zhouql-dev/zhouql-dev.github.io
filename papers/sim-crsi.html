给自我改进的 Agent 配一本工程日志：Google 的 SIM 把递归自我改进做成了可持续的事

Self-Improvement Memory Enables Continual Recursive Self-Improvement
arXiv 2611.18856 · Google Cloud AI × Google DeepMind × Penn State · 2026-11-13 · 35 页

Agent harness 的递归自我改进（RSI）这两年进展很快：让一个 LLM 优化器反复阅读执行轨迹、提出 harness 修改、跑评估、择优保留，进化出的 harness 能明显超过人手写的 seed。Anthropic、Meta-Harness、RRSI 都属于这一路线。

但几乎所有这类工作都有一个默认前提——模型和 benchmark 不变。一旦模型换代或任务分布变化，进化成果怎么办？Google 这篇新论文专门研究这个问题，结论有点扎心：把进化好的 harness 直接搬去新模型或新数据集，起点可能比 seed 还差。

01沉默的代码会背叛你

两个实测数字。Opus 5.5 上进化出的 workspace harness，放到 Gemini 3.8 Flash 上只得 68.41 分，而 Gemini 自己的 seed harness 有 73.89 分——进化成果一迁移就成了负资产。文本分类域同样：FewShotAll 进化出的 harness 迁移后 72.92，seed 是 75.72。

为什么？因为 harness 只是一堆沉默的代码。它说不出自己为什么被改成这样、每一处修改预期修复什么、验证结果如何。新环境里的优化器只能靠猜：有些改动照单全收却不知道用途，有些被误改坏了。论文里最生动的细节是，无记忆的优化器把继承来的完成门控当成了自己第一轮发明的——它根本不知道这是上一代优化的遗产。

论文把这个问题正式化为 CRSI（Continual Recursive Self-Improvement）：RSI 不该只发生在单一 setting 里，进化能力要能跨模型换代、跨数据分布地延续下去。这是第一篇把「harness 优化的持续学习」当作正式 setting 来做的工作。

02SIM：给优化器的记忆，不是给执行者的记忆

现有 agent memory 工作几乎全在服务内层 agent——检索工具、存对话、记用户偏好。这篇论文做了一个记忆对象的反转：SIM（Self-Improvement Memory）是给外层 harness 优化器的记忆。那个「改进 agent 的 agent」，此前一直是裸奔的。

SIM 的记忆单元按复发性问题组织：一个根因诊断（比如「任务未验证就提前宣告完成」）下面挂一串尝试记录，每条记录包含修改内容与理由、预测结果与观察结果、以及出处（哪个域、哪个 benchmark、哪一轮）。一个 entry 大致长这样：

ENTRY 结构 根因诊断 → [(修改 + 理由，预测结果 → 观察结果，出处)1, …, (·)j]

三个设计选择值得展开。

预测先行

优化器提出修改时必须先写下「预计修复哪些任务」，评估后再逐项核对。这把记忆从流水账变成了可问责的假设检验——错判会被永久记录在案。事后诸葛亮式的经验总结，在这里写不进记忆。

失败也入账

每轮只有被选中的修改才写入记忆，但包括回归和失败的。没被选中的候选不留档，选中的败笔必须留——负证据防止后来者重蹈覆辙。这和人类工程复盘的经验一致：最有价值的教训往往是「我们试过，不行」。

不检索、全量读

proposer 和 selector 每轮读完整记忆，不做 RAG、不截断。理由是 harness 问题只有几十个量级，结构化后全塞进 context 完全可行。这算是对「记忆必须配检索」惯性的一次工程反例：规模小、结构好的记忆，全量读反而可靠——检索漏掉的恰恰是跨域最该带走的那条。

03四种迁移条件的对照设计

实验的核心设计是把「带什么经验迁移」拆成四个条件，前三者共享同一个进化好的 harness HS，预算（轮数、候选数）完全匹配——这是本文证据可信的关键：

迁移条件起点 harness携带的记忆
Cold Start（冷启动）seed H0无——从零进化
Harness Transfer进化 harness HS无——只有沉默的代码
Problem-Only Memory进化 harness HS仅根因诊断清单（没有尝试史）
Full SIM进化 harness HS完整记录：根因 + 修改 + 预测/观察 + 出处
 四种迁移条件。后三行共享同一份源域进化 harness，记忆在整个目标域 RSI 期间持续参与更新。

第三战：十组配对实验，统计上最硬的证据

第四战：模型代际链，经验跟着版本走

把 harness 和 SIM 从 Gemini 2.5 Flash 一路传到 4 Argon，每代换代后续跑。四代里 CRSI 三代胜过从头进化（3.5 代 +3.5 分、3.8 代 +1.6 分），只在 4 Argon 上落后 0.8 分——模型能力越强，历史包袱的边际收益递减，这本身是个合理的边界信号。

第五战：遗忘测试——迁移与保留能不能兼得

continual learning 的经典担忧：学了新域，旧域掉分。论文在源域 TB2.1 的 225 个 rollout 上做保留测试。共同起点 90.22：完整 SIM 只丢 3 个成功 rollout（88.89），仅诊断丢 4 个（88.44），无记忆迁移丢 6 个（87.56）。同时完整 SIM 在新域 TB4 上净赚 6.67 分，仅诊断版只赚 0.61。迁移与保留兼得——这在 continual learning 里是少见的干净结果。

05案例拆解：完成门控的跨域旅行

全文最有味道的细节是同一个「完成门控」在源域和目标域的两段故事，它把 SIM 的价值讲成了具体剧情。

源域（TB2.1）：执行验证门控的诞生

任务：搭一台 git 服务器，要求从外部机器走 SSH 克隆、push、HTTP 访问全部可用。失败 rollout 里，agent 把仓库、hook、web 服务都配好了，然后用容器里预存在的 ubuntu 账户本地测试——每条命令都成功——于是宣告 task_complete: true。而校验器从容器外以 user 身份克隆：SSH 拒绝不存在的用户，push 失败，404。

seed harness 的完成检查只是让模型再说一遍「我确认完成」——问的是意图，不是证据。根因诊断被记入 SIM：结束 episode 是 agent 的特权，却不需要任何执行证据。修复是 137 行的 execution_gating_interlock.py：一个跨回合状态机，上一回合有解析错误或没有命令真正执行时拒绝完成宣告，最多拒绝三次。这条记录带着预测（预计修复哪些任务）和观察（实际效果）进了记忆。

目标域（TB4）：同一个门控的新考题

TB4 的任务变了：不仅要求「跑通」，还要求解质量——可行 ≠ 最优。继承来的门控只验证「命令执行成功」，管不了「方案是不是最优」。带 SIM 的续跑里，P5 entry（过早宣告完成，源域）继续有效，优化器新开 P8 entry（解质量验证，目标域），给门控扩展出新的检查谓词。两条 entry 都指向那个继承的门控，但没有父子链接——它们是各自独立进账的经验。

对照组：哑巴优化器的迷惑行为

不带 SIM 的续跑拿到同一个门控，却把它当成自己第一轮发明的；无 SIM 的运行甚至一度回退了继承的指导。图 8 把这种分化拍得清清楚楚：同一份 harness，同一条门控，带记忆的一方在扩展它，不带记忆的一方在误改它。

07两个值得单独记下的洞察

洞察一 · 元层面的 Continual Learning 这篇论文其实是把 continual learning 的经典主题——迁移、遗忘、干扰——搬到了元层面：学习的对象从模型权重换成了 harness 代码。遗忘实验就是 CL 的 retention 实验，配对实验就是 CL 的 transfer 实验。CL 社区积累的方法论直觉，忽然对 agent 工程全部适用。
洞察二 · 记忆属于优化器 记忆对象反转是这篇论文最深的一刀：SIM 是给外层 harness 优化器的记忆，不是给内层执行 agent 的。现有 agent memory 工作几乎全在服务执行者——检索工具、存对话、记偏好；而「改进 agent 的那个 agent」一直裸奔。给谁配记忆，决定了系统能沉淀什么。

它也补上了 Anthropic 那条 RSI 路线缺的一环：Anthropic 研究单 setting 内的改进闭环，这篇解决闭环之间的经验交接。两者拼起来，才是一个完整的自我改进系统生命周期——进化、沉淀、迁移、继续进化。

08泼两盆冷水

+2.36 分的绝对量级不大——TB4 的分数区间本来就只有 18 到 21 分，这是个小分数域里的显著提升，不是普适的质的飞跃。而且除 coding 外，其他域都只有单次运行，六 setting 全胜的好看成绩缺统计置信度。

SIM 没有淘汰或压缩机制。迁移链条拉长后，记忆膨胀和 context 成本怎么办？论文没讨论。永不遗忘也可能变成包袱——源环境的诊断在目标环境失活（SMILES 归一化、refusal handling 都是实例）之后，该不该清掉？按「全量读」的设计，每条死记忆都在持续消耗注意力。这是下一个显然的研究问题。

09给做 agent framework 的人

对正在构建 agent 系统和框架的工程实践者，这篇论文最值钱的是可以直接抄走的 entry schema：根因键控 + 预测/观察对 + 出处。它就是框架自改机制的日志格式——每一次自我修改都强制回答三个问题：为什么改、预期修什么、实际效果如何。做不到这三问的自改，就是不可问责的自改。

三条可落地的推论：

一，记录失败比记录成功更值钱。选中的败笔必须留档，负证据防止重蹈覆辙——这和直觉相反，但论文的 Problem-Only 对照已经证明：只留结论不留过程，经验几乎不带电。

二，小而结构化的记忆，全量读优于检索。当记忆条目在几十的量级且按根因组织时，别急着上向量库——检索漏掉的恰恰是跨域最该带走的那条。

三，预测先行是免费的问责机制。修改前写预测、评估后核对，一次调用都没多花，却把「自改」从玄学变成了假设检验。任何 self-improving agent 都该从这一步开始。
