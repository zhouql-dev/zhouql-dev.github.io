推理路由早已把"按 query 分流"玩熟了，但算法侧已经推进到 token 级：R2R 证明只需把 5% 的 token 交给 32B 大模型，就能对齐其质量——而 query 级路由要把 40% 的请求给大模型。5% 对 40%，成本结构的代差。问题是：这批算法几乎没一篇能高效跑起来。

01为什么现有系统跑不动

先看数字有多尴尬：R2R 官方实现在并发 4 下吞吐 77 token/s，比单跑 32B 大模型（145 token/s）还慢——省了算力，却赔上了速度。根子在 vLLM、SGLang 这类系统的隐含假设：一个 batch 里所有请求属于同一个模型，同步走每一步解码。token 级路由把这条假设打碎了——请求的目标模型在每个 token 都可能变。具体卡在三件事：

步调失同步。大小模型的单步延迟差一个量级，绑在同一个 batch 里，每步都得等最慢的模型，快模型干瞪眼。批次准入延迟。路由过去的 token 到达时，目标模型多半正在解码上一个 batch，新请求只能干等，batch 被切碎、气泡不断。实现复杂度。现有系统根本没暴露"每步决策路由"的编程接口，想加 token 级路由得大改引擎内部，还要跟 continuous batching、prefix caching 这些紧耦合特性缠斗。

02设计：编程一套抽象，执行另一套

TokenRouter 的核心原则一句话：request-centric programming, model-centric execution——开发者按"单个请求怎么在模型间流动"来写路由逻辑，运行时按"每个模型一个自治子服务器"来跑。编程和执行彻底解耦，这是系统设计的老套路，用在路由上依然锋利。

编程侧只暴露三个函数：route（每步解码后，根据 logits/隐状态决定每个请求去留）、send（把请求状态打包成 PeerReq 发给对端，携带对端未见过的 token 后缀和位置锚点）、receive（接住对端回来的 token，默认全收）。论文用约 30 行代码实现了 R-Stitch 的完整路由语义——包括"扔掉刚才那个高熵 token、让大模型从那个位置重新生成"这种细节。对客户端是 drop-in 的：外部接口和 vLLM/SGLang 完全一致，后面挂多少个模型客户端不感知。

执行侧是三循环解耦：标准服务器的 client-server 循环、decoding 循环之外，加了一条 inter-model 循环专门处理跨模型请求。每个子服务器按自己的节奏走，谁也不等谁。路由出去的请求标记为 pending 状态——KV 槽位保留、跳过 prefix 匹配，对端回来时直接切回 running，跨模型切换的开销被压到接近一次 token 追加。对照实验里，没有这个机制的 SGLang 标准方案每次切换都要重做 prefix 匹配和 KV 分配，长输出负载下吞吐直接丢掉 58–85%。

调度上用 delayed batching：收到请求先缓冲，攒够阈值 B 再开批。直觉是牺牲队头请求的一点点等待，换取后来者大幅减少准入延迟——把稀疏到达的路由 token 攒成整批。阈值 B* 不手调：把路由过程建成离散时间马尔可夫链（DTMC），从吞吐模型里解析求最优。这是论文里我个人最喜欢的部分——用分析模型替掉手调超参。

03效果：2 倍到 64 倍，但要会读

5 种路由算法（CITER、R2R、R-Stitch、Co-LLM、ME）× 3 种负载（AIME 短/长输出推理、SWE-Smith agentic 多轮），15 种组合上，TokenRouter 对更强的那个基线，解码吞吐提升 2.01–64.15×，端到端延迟降低 2.03–63.64×。

64× 这个数要看清楚来路：它来自 CITER 在长输出推理下对比 SGLang 标准方案（4.49 token/s）——对手没做异步、每次跨模型切换重做 prefix 匹配。对最强基线 R2R 官方实现，提升是 1.99–3.21×，且在 4 组大小模型配对（0.6B/1.7B/4B × 8B/32B）上都稳。增益分解也诚实：工程优化 1.71×、异步执行 +1.29×、delayed batching +1.25×，合计 2.76×——没有一层是虚的，但也没有哪一层是魔法。

04帕累托前沿：从理论上更优到实际占优

系统补齐之后，最后一环才闭合：在 AMC23 上固定内存配额公平对比，TokenRouter 把 token 级路由推到新的吞吐-准确率帕累托前沿——过去"细粒度路由理论上省钱但实际跑不快"的尴尬消失，对 SGLang 上的 query 级路由（RouteLLM）变成全面占优。算法论文画了两年饼，这是第一批让饼真正端上桌的系统工作。

05冷水

数学模型的假设边界。DTMC 建模假设相邻两次路由之间的 token 数服从几何分布——大多数算法满足，违反的边角案例论文自己承认不管。帕累托实验只有 AMC23 一个数据集。结论方向可信，外推幅度存疑。大倍数里有对手躺平的成分。Co-LLM 官方实现 3.46 token/s、CITER 官方 17.16 token/s，这种水平的基线贡献了表格里最扎眼的那几行——对工程强者的真实增益以 R2R 的 2–3× 为准。同行评审还没过。NeurIPS 2026 在投。

06工程意义

一个领域的算法开始成批出现、而系统跟不上时，瓶颈就从算法侧移到了系统侧。token 级路由正处在这个拐点，TokenRouter 是第一批认真做这一层的工作，代码已开源（thu-nics/TokenRouter）。对做推理部署的人，两条可以直接抄：

第一，抽象分层照搬。request-centric / model-centric 的解耦——编程模型描述语义，执行模型负责性能——这个套路从 RPC 到数据库到现在的路由系统屡试不爽。下次你给多模型推理做编排，先问自己：语义层和执行层分开了吗？

第二，分析模型替掉 grid search。调度阈值不用扫参，DTMC 一推有闭式解。系统调参能解析就别枚举，这是被忽视的老手艺。

顺带一提，这篇和昨天的 MASS 形成有趣的对照：MASS 在认知层分工（agent 角色各司其职），TokenRouter 在算力层分工（大小模型各干各的活）。多智能体的本质都是"把异构单元组织起来"，只是组织发生在不同的层——而两篇论文都在回答同一个问题：组织本身的开销，谁来买单。

算法画了两年帕累托前沿，系统终于接住了——2 倍到 64 倍的差距不在算法里，在基础设施里。
