循环 LLM 不用从头训练了：Loop Residuals 把现成模型微调成「会多想几圈」

从头预训练一个循环模型，账算不过来；把现成模型微调成循环，分数又涨不动。这道两难，被这篇论文拆掉了。病根在信息通路：所有现有循环设计都把前面 loop 的输出压进一条窄通道。修法只有两个动作，结果是用微调级成本，让循环深度第一次成为预训练 LLM 上真实可用的 scaling 轴。

让模型在推理时「多想几圈」，参数一个不加——免费午餐的门票，过去是整次从头预训练，而且吃了还未必饱。这篇 ICML 2026 论文换了一条路：不重训，直接把现成 LLM 微调成循环模型。Qwen3-1.7B 平均分 43.2 → 55.8（+29.1%），是此前最强循环基线（+13.9%）的两倍多；LoopRes 加持的 4B 模型，分数反超 SFT 的 8B。为什么直接微调涨不动？病根在循环之间的信息通路——打开它，微调级成本就能兑现循环的全部承诺。

一画了七年的饼：重训太贵，微调不涨

把 Transformer 的同一组层反复执行，想法至少可以追到 2019 年的 Universal Transformer——参数量固定，深度按需增长，理论上优雅，实践上却始终没能打赢同规模的堆叠结构。2025 年前后这个方向换了打法：既然从头训练代价太大，那就拿来现成的预训练模型，把中间的层打包成一个共享块，微调成循环结构。Huginn、Ouro 走从头预训练路线，CloseLoop、TaH2、InfiLoop、BRT、Hyperloop 走微调路线——后者只需预训练零头的算力，还能白捡底座模型学好的能力，看起来是更聪明的路。

但结果一致地令人失望。从头训的循环模型在同等成本下增益平平甚至为负；微调路线的最好成绩，相对普通 SFT 也只是零点几到十几个百分点的涨落，而且不同方法之间互相拉扯，谁也没能拉开差距。loops 这个方向眼看要凉。

这篇论文的第一个贡献，是把所有这些方法的共同病根挑明了：无论循环结构怎么变花样，后面的 loop 想在前面的工作之上叠加信息时，能拿到的都只有一股残差流。第 t 圈的输出被压进一条窄通道，传给第 t+1 圈。你叠了七圈，可用信息还是那一管子——深度加了，通路没加，增益自然上不去。

二病根确认：直搬 AttnRes，三个坑

最直接的修法，是让每层直接「看」前面所有 loop 的输出。Kimi 的 Attention Residuals（AttnRes）恰好提供了这个机制：每层不再吃单一残差流，而是对前面所有块的输出做一次 softmax 加权聚合，需要谁就多看谁。问题是，AttnRes 是为普通 Transformer 设计的——那里每个来源是不同的层，内容各异、数量固定。放进循环，这两个前提全崩。论文用一组可视化把崩坏钉死在三个坑上：

坑一：迭代产物长得太像。同一个 block 跑七圈的输出彼此高度相似——图 (a) 显示块内（同层跨 loop）的余弦相似度远高于块间。而 AttnRes 的 key 恰恰是从内容算出来的：来源趋同，分数就趋同，注意力权重在大面积迭代产物上塌成一团（图 b、d 的箭头高度几乎抹平）。

坑二：定型太早。图 (c) 显示，输出 query 的范数在微调的前三分之一就收敛到位——连接模式在模型还没学会区分七圈输出之前就锁死了。之后内容 key 只能通过隐状态间接变化，为时已晚。

坑三：抄近路。来源随 loop 越滚越多，层可以跳过中间环节直接抓最早的结果。量化证据很扎心：贯穿全部七圈的最长路径（图 e），权重从三圈时的 33.7% 跌到 0.05%——深 loop 白跑，有效深度根本没加。

窄通路的本质：深度增长靠的是「在前面工作之上叠加」，而所有现有循环设计只给叠加留了一条单车道。AttnRes 的聚合思路是对的方向，但它假设来源内容各异、数量固定——循环恰好同时破坏这两个假设。

三LoopRes：两个动作，打在要害上

LoopRes 建立在 Huginn 式循环骨架上：全部层切成 prelude（进循环前跑一次）、core（循环体，重复 L 次）、coda（出循环后跑一次）三段，core 取中间一半的层。

在这个骨架上，LoopRes 做了两件事。

第一件：给每个来源发身份牌。AttnRes 的注意力打分只用内容 key。LoopRes 给每个来源配两个 key，并联打分：

αs = exp( qloopᵀ kloops + qᵀks ) / Σs′∈𝒮 exp( qloopᵀ kloops′ + qᵀks′ )qloopᵀkloops：loop-aware 打分（结构身份）；qᵀks：内容打分。ks = RMSNorm(vs)，随 token 内容变化。

loop-aware key 是一个可训练向量，编码「你是第几个 loop 的第几个 block」的坐标。内容会趋同，但坐标不会——这就绕开了坑一。它直接参与优化，不依赖隐状态慢慢变化——绕开了坑二。初始化也有讲究：loop-aware key 从 N(0, I) 采样，query 全零初始化，起点是均匀混合，之后让数据自己决定两种 key 的分工。

第二件：只准看最近一圈。每层的注意力视野限制在最近 W 个 loop 的输出（加上 prelude 和当前 loop 的部分和），早期 loop 一律不可见。抄近路的路被拆掉——每个 loop 被迫在最近的结果上增量构建，坑三消失；注意力池子不再随深度膨胀，来源数锁定为 (W+1)B+1，开销恒定。实验发现 W=1 最优：视野最窄，效果反而最好。

W=1 的最优解耐人寻味：LoopRes 实际学到的接近「递归增量更新」——每圈只看上一圈的产出。经典 recurrent 的直觉，在现代预训练模型里借 attention 的壳复活了。

工程上还有一个容易被忽略的坑：聚合前面所有来源的输出意味着读取一大片 KV，朴素实现要多花 54.9% 的训练步时间和 47.5% 的峰值显存。LoopRes 用一个 FlashAttention 风格的 Triton 融合 kernel，把输入聚合和注意力计算合并成单次 pass，开销压到 +4.8% / +0.7%。

五Scaling：更陡的斜率、更高的天花板

比单点分数更重要的是 scaling 行为。LoopRes 把计算花在「多跑几圈」上，而 loop 深度是一条可以和 thinking budget（生成长度）、模型尺寸叠加的独立轴。

把 loop 深度从 2 扫到 11，每条曲线对应不同的 thinking budget（1K → 30K tokens）：两条轴互相独立、都能换分——loop 深度提高平均分，thinking budget 拉长增益曲线。深度的甜点位在 L=3，超过 L=5 后收益饱和。这给了部署一个明确的旋钮组合：小预算用深 loop，长输出拉 budget。

斜率同样关键：从 1.7B 到 8B，LoopRes 得分随解码计算增长的曲线比 SFT 更陡——天花板更高，长输出场景下达到同样分数花的计算更少。也就是说，这不是一个会随规模消失的技巧，规模越大，它买到的深度越值钱。

六模型学到了什么：迭代结构 + 逐 token 自选深度

LoopRes 为什么涨？论文对训练好的模型做了一轮解剖，答案比「分数涨了」有意思得多。

它学出了迭代结构。图 (a)：第一个 block 的输出主要由自己上一圈的输出更新（L1B2 ← L1B1 的权重占大头），第二个 block 则主要依赖当前圈第一个 block 的结果——每个 loop 在前一圈的成果上增量加工，正是设计初衷的行为。图 (b)：把 L 拉到 7，这个模式在所有 loop 上稳定成立，不是局部巧合。

loop-aware key 是选择的主导者。图 (c) 用 Shapley 值拆解两种 key 的贡献：loop-aware key 主导来源选择，且随深度增加贡献更大——结构身份信息在深循环里比内容信息更关键。

内容 key 学会了逐 token 自选深度。图 (d)：把 token 按内容 key 的偏好排序，"But"、"Wait" 这类连接词/简单 token 偏好浅层输出，数字和数学符号偏好深层输出。同一个模型里，难 token 多转几圈，简单 token 少转几圈——深度分配是逐 token 自适应的，这是从注意力权重里直接读出来的行为。

和 AttnRes 对比更能说明问题（上图）：AttnRes 的内容打分几乎是一个「固定偏好」——不管当前 token 是什么，权重分布都差不多，还会给第一圈留可观的捷径权重；LoopRes 的内容打分方差主要来自「逐 token 变化」的分量——loop-aware key 接管了固定偏好这部分，把内容 key 解放出来专管「这个 token 该看多深」。分工干净，各司其职。

九局限与下一步

论文的局限交代得很诚实：只在数学和代码上验证，任务域之外的迁移未知；只做了 SFT，RL 和 on-policy distillation 都没碰；L=3 的甜点位说明深度收益会饱和，「无限深循环」不存在。

但有两个方向值得押注。其一是 RL + loop：循环把「单位 token 的计算」变成可调参数，RL rollout 用深 loop 换长思维链，推理成本可以直接砍下来——论文自己的管线图把这一点画成了下一步的终点。其二是作者埋的伏笔：解剖显示学到的连接模式高度结构化，暗示一套固定的连接规则可能就能拿到大部分收益——把可学习的注意力换成更简单的确定性方案，是顺理成章的简化。

十结语

回头看，这篇论文的方法部分出奇地朴素：给注意力加一个结构 key，把视野砍到一圈。它的分量全部来自诊断——先证明所有循环失败共享同一个病根（窄通道），再证明直接开通道还不够（AttnRes 的三个坑），最后才给出两个刚好够用的修复。每一步都踩在证据上。

对工程实践者，这篇论文的可用结论是：拿现成预训练模型，按 Huginn 骨架把中间一半层打包成 core，套上 loop-aware key 和 W=1 窗口，2 倍计算、L=3 起步——这是目前「加深不加参」唯一被大规模验证过的配方。对研究者，它把 loop depth 放上了 test-time scaling 的牌桌：推理时的性能，从此多了一个可以旋的钮。

深度不是堆出来的，是喂出来的——每一圈都要真正吃到上一圈的产出，循环才配叫深度。
