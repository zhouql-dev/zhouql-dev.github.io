合成数据 预训练 负结果 数据受限

同算力下，先喂合成数据其实更差：881M 模型的负结果

arXiv 2610.40051 · 2026-10-31 · Cohere / UCL AI Centre / MIT

预前训练（PPT）这件事，前人报的是增益，这篇报的是否定：算力一样时，把预算分给合成数据从来没赢过纯自然语言，4 种课程、3 种数据制度、最大 881M 参数，验证 loss 上一次例外都没有。

一、这笔账要分两次算

作者把问题拆成两笔账：合成数据如果是额外加的算力，它帮不帮得上忙；如果它要和自然语言抢同一份预算，还值不值。前一笔账在小预算上成立，后一笔账在验证 loss 上全部不成立。这个区分是全文骨架，后面每个实验都在回答它属于哪一笔，所以“PPT 没用”这个说法必须带上括号：在同算力下没用。

PPT 的做法是在正式预训练前先用合成数据训一段，希望模型带着“计算结构”的先验进入语言学习。课程大致三类：形式语言（k-Dyck 练括号配对）、算法任务、以及从随机初始化的神经网络里采样出来的序列（NCA 是二维格点上的元胞自动机）。本文测四种：k-Dyck、NCA、DeclRef（自己造的作用域与引用语料），再加 code 这种真实文本，另用 C4 作纯自然语言的对照。前人报的增益不小：1.6B 模型上 NCA 把困惑度降 5.7%，1B 模型上 k-Dyck 把交叉熵降约 0.6%。

复核从最容易被检验的一处开始：复现 NCA 那组实验。400M 的 Llama、约 9B token 的 OpenWebText、164M 的 NCA token，困惑度降 5.4%，效应复现出来了。但原文对同一配置报的是 8.6%，差额作者归到配置没写全上：层数、隐藏维度、数据切分都得自己估，估完就照这一套跑。

二、只改一处初始化，增益就没了

但只改一处初始化，结论就翻了：把 token embedding 从 N(0,1) 换成 N(0,0.02)，基线自己就降了 9.0%，比 PPT 那 5.4% 还多；再把同一套初始化用到 NCA 上，两根柱子并到一起，分不出差别。这组只隔离初始化这一件事，没有在新初始化下重调 PPT 的 token 数，所以它回答的不是“NCA 最好配置”，而是“基线还剩多少余量”。

一个没被控制的变量，足以造出一个看上去干净的显著差异。 我的判断是：这不算前人做错，而是“换课程、其余全固定”的设计天生看不见基线还剩多少余量；基线没调到位时，任何给它加先验的操作都显得有用。作者把这条写成了方法论建议：以后做 PPT，把初始化也当成要扫的变量，对基线和 PPT 一视同仁。

三、加法算力下它赢，抢预算时它全输

接着问加法算力。固定自然语言预算、额外给 PPT 一份算力，50M 和 100M token 上 NCA 与 k-Dyck 都赢了基线，说明合成语言确实能塞进一点先验；到 1B token，在 spectral 初始化下所有方法都落进基线的种子波动里，不再分得出高低。

原文的措辞很小心：小预算上的增益与初始化无关，1B 上的增益只相对于“没调好的基线”存在。同一张图里叠着两个效应，一个是预算，一个是初始化，读到哪一层，结论就不一样。这也是这篇最容易被引用错的地方——只看标题会以为它全盘否定，其实它承认了小预算上的增益。

先看零和：同样的钱，买先验还是买语料

真正决定成败的是下一组实验：总预算固定，PPT 拿走其中 α 的比例，剩下的给自然语言。这一步把“加法”换成了“零和”，问题也从“有没有用”变成“值不值这个价”。

C_{\text{PPT}} = \alpha C,\quad C_{\text{NL}} = (1-\alpha) C

这句在说什么：总预算是一块固定的蛋糕，α 是切给合成数据的那一刀。α = 0 就是把整块蛋糕都给自然语言，α = 5% 是先花 5% 喂合成数据、再拿剩下 95% 学语言。问题于是变成二选一：同样的钱，是买先验，还是买更多语料？

设定一：数据荒里，重复读更划算

数据受限设定把自然语言卡在 100M 个不重复 token，于是每一份额外的算力只能换成重复训练。结果是任何比例的 PPT 都让验证 BPB 变差，超过 5% 后曲线走平，说明这笔钱在 5% 处就花完了。这一点比“PPT 没用”更具体：连数据荒这个最有利于合成数据的场景，重复读同样的语料也更划算。

设定二：881M / 50B token，还是没赢

第二格把规模拉上去：881M 参数、50B token，每个参数约 57 个 token，是 Chinchilla 最优点的大约 12 倍；PPT 拿 0.5B token，自然语言 49.5B。这个预算已经比前人 PPT 工作里最大的一组还大，验证 loss 和 DCLM CORE 上，NCA 与 k-Dyck 都没赢。

设定三：放开数据，也没见反超

第三格放开数据量，1×10¹⁸ 到 9×10¹⁸ 三档预算，每档都把模型尺寸搜到最优——最优尺寸本身还随方法浮动，1×10¹⁸ 上从 179M 到 186M 不等。作者给每种方法拟合幂律，没有一种的乘常数更低，也没有一种的指数显著更大：不只现在不赢，也没有随规模反超的迹象。

下游基准更微妙。聚合的 BLiMP 与 DCLM CORE 上多数方法持平或略低；少数例外集中在最小预算，比如数据受限下 DeclRef 10% 把 BLiMP 从 0.721 抬到 0.731。但 C4 这个纯自然语言对照组拿到同一档分数，说明这些例外更像噪声。拆到单任务上，有些语法现象确实变好，另一些同时变差，加总就被抹平了。

四、它为什么会忘

机制部分是我认为全文最有价值的一段。作者在 2.7×10¹⁹ FLOPs 的预算下追踪 PPT 语料自身的 BPB：进入自然语言阶段的那一刻曲线立刻上翘，模型开始忘掉刚学会的东西。作者还排除了“忘记是应该的”这个解释：code 语料的 token 在自然语言阶段仍会出现，模型本该继续学到，它的 loss 照样上翘。

把同样 5% 的算力改成全程交错，遗忘就没有了，PPT 语料的 BPB 全程下降；但自然语言上的改善并不显著，而且这组没做完整调参，所以只能说“交错不吃亏”，不能说“交错更好”。于是“前端塞一段”这个做法本身成了问题，而不是合成数据本身没用。

五、三个容易被引用错的地方

边界要说清：9×10¹⁸ FLOPs 以上没法完整搜参，高于这个预算的实验只扫了学习率；PPT 占比固定在 1% 和 5%，介于两者之间、或者随总预算变化的比例都没测；最大模型 881M，再大的规模这篇不给答案。还有一处口径上的坑要单独交代——

\mathrm{ppl} = e^{\mathcal{L}}

这句在说什么：困惑度就是 loss 取指数，所以同样的 loss 差，在困惑度上显得更大。前人报的“降 5.7% 困惑度”，换算回 loss 大约只降 2% 出头；这篇统一报 BPB，差异看上去就更小。这不是谁在夸大，而是两把尺子量的不是同一个东西。

六、我的读法与建议

负结果的价值不在“否定了什么”，而在“把哪个变量摆上了台面”。 这篇摆上台面的是初始化方案；它必须证明自己不是靠弱基线取胜，作者用 spectral 初始化、幂律拟合、下游基准三处互证，这一点做到了。我的读法是：把它当“合成数据没用”引用是错的，把它当“前端塞数据的收益可能来自基线欠调”引用才对。

如果要做合成数据，我会先改两件事：把合成数据交错进全程而不是前置，并且把 PPT 语料上的 BPB 当作常规监控，用来看先验是否还在。放到我们写过的几篇里看，《循环 Transformer 到底值不值：缺参数和缺算力，答案相反》是同一种账本思路，《多采样反而更差：RLVR 的 pass@1 是买来的》讲收益与代价的定价，这篇则把“先验到底有没有留下”测了出来。
